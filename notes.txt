# ⏰ OLED Clock Display with DS3231 RTC + Temperature + LED Breathing Animation

A clean, modular digital desktop clock built on the **Arduino Nano**.

---

## 🧩 Modules

- 🖥 **SSD1306 OLED** – I²C display shows time and alternates header between date and temperature  
- ⏱ **DS3231 RTC** – Precise real-time clock with onboard temperature sensor  
- 🔊 **DFPlayer Mini** – Startup sound and audio feedback (pins 8 = RX, 9 = TX)  
- 💡 **NeoPixel LED strip** – Smooth cyan breathing animation (5 LEDs on D6)

---

## ⚙️ Electrical Connection (5 V Safe)

| Module           | Pin on Nano            | Notes                     |
|------------------|------------------------|---------------------------|
| OLED SSD1306     | SDA → A4 / SCL → A5    | I²C address: `0x3C`       |
| DS3231 RTC       | SDA → A4 / SCL → A5    | Shared I²C bus            |
| NeoPixel LED     | D6                     | 5 LEDs, 5 V, common GND   |
| DFPlayer Mini    | RX → 9 / TX → 8        | Uses AltSoftSerial        |

> 💡 All I²C devices share the same SDA/SCL lines — no conflict.

---

## 🧠 Features

- Big centered time `HH:MM` with **blinking colon**
- Seconds displayed in small font (bottom-right)
- **Top-right header alternates** every 15 seconds:
  - `Sa29` (day + date)
  - `23C` (temperature from RTC, rounded to integer)
- NeoPixel **cyan breathing animation** (non-blocking, smooth)
- DFPlayer plays **startup sound** (`0001.mp3`) at low volume
- **5 V-safe** operation for Arduino Nano
- **Partial screen updates** to minimize OLED flicker

---

## 💻 Libraries

Install via Arduino Library Manager or PlatformIO:

- Adafruit GFX Library
- Adafruit SSD1306
- RTClib (by Adafruit)
- Adafruit NeoPixel
- DFRobot DFPlayer Mini

## 🚀 Quick Start

Install required libraries
Wire components per connection table above
Place a 0001.mp3 file on your DFPlayer microSD card (optional but recommended)
Upload code to Arduino Nano
On first boot, RTC syncs to compile time (__DATE__, __TIME__)
Enjoy your sleek, animated desk clock!
🔌 Power via USB or external 5 V — both work safely.

🔧 Technical Architecture
Communication Protocol (PC ↔ iGO)
SERIAL COMMUNICATION (115200 baud):

Commands from PC to iGO:
├─ CONFIG:key=value               → Update settings
├─ NOTIFY:app|title|body          → Send notification
├─ THEME:upload                   → Start theme transfer
├─ AUDIO:upload:filename.mp3      → Upload audio file
├─ SYNC:calendar                  → Sync calendar data
├─ FIRMWARE:update:v2.5.0         → Firmware update mode
├─ QUERY:battery                  → Request battery status
└─ TIME:sync:1706452800           → Set RTC time

Responses from iGO to PC:
├─ STATUS:battery=78%,charging=1
├─ EVENT:alarm_triggered:07:00
├─ LOG:notification_displayed:Slack
├─ ACK:command_received
├─ ERROR:invalid_command
└─ DATA:sensor:temp=24.5,pressure=1013.2
File Transfer Protocol
For large files (themes, audio, firmware):

1. PC sends: FILE:START:filename.mp3:size=2451234
2. iGO responds: FILE:READY
3. PC sends data in 512-byte chunks with checksums
4. iGO responds after each chunk: FILE:CHUNK_OK
5. PC sends: FILE:END:md5=a1b2c3d4...
6. iGO verifies and responds: FILE:COMPLETE

During Day:
├─ iGO shows next meeting countdown
├─ Voice alerts 15 min before meetings
├─ Charges phone via USB-A port
├─ Logs Pomodoro sessions

Load-Shedding Hits:
├─ iGO switches to battery
├─ Keeps showing time & alarms
├─ Desktop app loses connection (PC off)
├─ User's phone connects via BLE
├─ Notifications now route through mobile app

Evening:
├─ Unplugs iGO, takes home
├─ At home, connects via WiFi
├─ Web app on tablet for evening planning
└─ Sets alarms for tomorrow

├─ WiFi connected to campus network
├─ Mobile app primary interface

├─ iGO offline (left in room)
├─ Works standalone (alarms still fire)
├─ Logs stored locally, sync when student returns

Evening Study:
├─ Student returns
